B. One sheet, two layouts, chosen by a hook Recommended

The era sets one hook, --share-layout: grid | rows, and sharesheet.js reads it when the sheet opens, the way switch.js reads --sw-travel. grid builds today's iOS 6 sheet unchanged. rows builds a header (title + ✕), a scrolling row of apps, an actions group and Cancel. Hooks in style.css lay out and hide each part. Each era's CSS only sets values.

Files

  • nav/sharesheet.js: reads the hook, adds a rows builder (header, apps row, actions, ✕). Same showShareSheet API, no caller changes.
  • style.css: the share hooks (the grid's "no hook yet" in docs/eras.md goes away).
  • ios6.css: tokens for the new parts. iOS 6 pixels stay the same (3x shot diff).
  • ios7.css, ios13.css, ios26.css: hook and token values only.
  • docs/eras.md hook list, plus a sharesheet.test.js case for each layout.

Trade-off

  • + Each era looks like its own iOS, in the app's usual shape: hooks plus values, zero layout rules in an era (the test still holds).
  • + The iOS 6 path is the code that runs today.
  • − The biggest of the three: a second builder in JS (~80 lines) and about 12 hooks.
  • − iOS 26 glass blurs over a moving page: it uses --i26-glass-blur so the solid fallback still works.

Recommendation: B

It's the only option where each era looks like its own iOS share sheet. It also matches how the action sheet and alert were split: layout in style.css hooks, and each era file only sets values. The iOS 6 grid stays the code that runs today, so iOS 6 has nothing to regress. The one new idea, JS reading a layout hook, is already used by switch.js and sheet.js. Planned build order: hooks and the rows builder with iOS 7 first, then iOS 13's card, then iOS 26's glass. Each step gets a live concept and era shots.
